VisionPort is an image-detection project with a FastAPI backend and an optional Streamlit interface.

You send an image to FastAPI using POST /detect or upload it in the API page at http://127.0.0.1:8000/docs.
gateway.py receives the upload and passes the image to the detector.
detector.py prepares the image and runs YOLOv8n using OpenVINO. It uses the project’s OpenVINO model and chooses an available device, such as GPU or CPU.
FastAPI returns the detections as JSON: object names, confidence scores, and bounding-box coordinates.
The optional Streamlit app in app.py displays the image with boxes drawn around detected objects. The API page shows JSON, not the marked image.
You also added POST /trace, which returns details and timings for the image-processing stages.

2. Weights – The learned knowledge

Weights are numerical values learned by the AI during training.

For example, the model learns which visual patterns help it identify a football.

Think of weights as the knowledge a student gains by studying.

3. Checkpoint (.pt) – Saved model

A checkpoint is a file that stores learned weights and usually the architecture and other information.

In your VisionPort project:

yolov8n.pt

This is the file you already have.

4. ONNX graph (.onnx) – Portable model

ONNX stands for Open Neural Network Exchange.

It stores the model as a graph of operations and weights.

It helps different AI frameworks and tools work with the model.

Think of it as converting a document into a format that different software can understand.

5. TensorRT Engine (.engine / .plan) – Optimised model

TensorRT converts the ONNX graph into an optimised engine for a particular NVIDIA GPU.

Its purpose is faster inference (making predictions).

Think of it as tuning a car engine for better performance.

Remember this difference:
- Architecture = Structure
- Weights = Knowledge
- Checkpoint = Saved model
- ONNX = Portable graph
- TensorRT = GPU-optimised engine

4. Precision
Precision determines how much memory each number uses.
Type	Bits	Memory per number
FP32	32	4 bytes
FP16	16	2 bytes
INT8	8	1 byte
INT4	4	0.5 bytes

Lower precision generally requires less memory.

7. Important points to remember
1. Different artefacts have different purposes.
2. PyTorch reads .pt files.
3. ONNX is a portable model format.
4. TensorRT optimises models for NVIDIA GPUs.
5. An engine cannot simply be renamed from an ONNX file.
6. TensorRT engines are hardware-specific.
7. Keep the original checkpoint because you cannot train from the engine.
8. Building a TensorRT engine requires a suitable NVIDIA GPU and TensorRT.
